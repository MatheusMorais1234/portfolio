FreelaManager: clients, contracts and installments for freelancers

A personal project I built alone between August and October 2026. Express API with Prisma and PostgreSQL, React front end, and a CI pipeline that builds the database from scratch on every commit.

What the system does

Each user only sees their own data. The demo has a ready account that is reset every 24 hours.

  • Individual and company clients, with Brazilian tax ID validation and address lookup by postcode (ViaCEP)
  • Contracts with status, amount and deadline
  • Automatic installments, up to 60, marked as paid in one click
  • Paid, due or overdue status, worked out from the dates
  • Dashboard with charts and due date alerts
  • Report by period with CSV export

How the parts connect

In production it is a single Express app: the API answers on /api and Express itself serves the React build.

  1. React 19Vite, React Router, Tailwind and shadcn/ui
  2. Express 5JWT with bcrypt, validation with Zod
  3. Prisma 7migrations versioned in the repository
  4. PostgreSQL 17on Neon; Hostinger runs the Node app

Decisions that keep every cent

A billing system cannot get an amount or a date wrong. These rules came from that.

Money as Decimal

Decimal in the database and a string in the JSON. In floating point, 0.1 + 0.2 does not equal 0.3.

Installments in whole cents

R$ 100 in 3 becomes 33.34 + 33.33 + 33.33. The leftover cent goes to the first installment, so the total adds up.

Due dates at month end

An installment due on Jan 31 falls on Feb 28 and goes back to Mar 31. Done carelessly, Jan 31 plus one month becomes Mar 3.

Status worked out, never stored

Paid, pending or overdue comes from paid_at and the due date, so there is never a stale status in the database.

Another user's data returns 404

Every query filters by userId. Asking for another account's record answers as if it did not exist.

CSV that opens in Excel

Semicolon separated and with a BOM, so accents and columns come out right in Excel set to Portuguese.

A bug the CI could not catch

The client page showed an installment due that same day as overdue, while the rest of the system showed the same installment as due.

The cause was the time zone. Dates are stored as midnight UTC, but that page worked out “today” from local midnight. In Goiânia, at UTC-3, the cut-off moved by three hours.

The tests passed because CI runs in UTC, where both calculations agree. The fix was to remove the rule from that page and use the same function as the rest of the backend, so “today” is defined in one place.

Tests and CI

Vitest and Supertest on the backend, against a real Postgres. Each test creates its own account and deletes it at the end.

  • Isolation between users
  • Tax ID validation
  • Installments that never lose a cent
  • Due dates at month end
  • Report totals
  • On GitHub Actions: starts Postgres, runs the migrations from scratch, the tests and the front-end build

What it does not have yet

The Google and Facebook sign-in buttons show on the login page, but they are only visual for now and marked as “coming soon”.
